# LC-011 网络生命周期控制器

沿用已批准连接器设计，顺序执行、TDD，不使用子代理。GitHub 项 LC-010 按用户要求跳过，不作为阻塞，也不标为通过。无 push、生产部署、迁移、网络设置变更。

现状：正式前端只有环境删除协调器，没有 VM 网络生命周期所有者。旧 Linux 恢复测试手工调用 close/restore，不能证明产品会在相应边界自动断开。

## 本轮切片

1. [x] 在 frontend/features/environments 增加浏览器兼容的网络生命周期控制器。明确连接才调用工厂；取消、offline、pagehide、连接器退出和恢复边界立即撤销当前网络。连接等待有上限，迟到 ready/onClose 不影响新一代；关闭网络不销毁 VM，不保存/重放客体命令。恢复后默认离线；同环境的旧 generation（即使 runtimeId 变化） 不可复用。
2. [x] 实际连接器会话适配器持有正式 client + guest network，异步授权响应受 AbortSignal 管理，关闭后不得创建 socket；失败关闭但保留 VM。不可包含开发探针身份、凭据持久化或任意 HTTP/命令接口。
3. [x] RED→GREEN 单元行为测试；再将真实 Worker/D1→WebSocket→Alpine 受控恢复验收接到新控制器，验证一次 POST、旧下载关闭、离线恢复及显式新 generation 后的新请求。保持受控目标的证据边界。
4. [x] 快速 VM 回归、类型/打包检查、checklist 校验与本地提交。

本轮不能用控制器单测或本地 Node Linux 代替 LC-011 的正式页面生命周期验收。LC-011 父项在正式运行时接线/实际浏览器取消、断网、退出、恢复矩阵通过前保持开放；LC-012 账户事件、LC-015 shadcn UI/账户运行时分别推进。只关闭有证据的子项，主清单 29/5/24 不变。
