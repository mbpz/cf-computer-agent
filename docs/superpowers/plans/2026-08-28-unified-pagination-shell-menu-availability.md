# Workbench Unified Pagination, Shell, and Menu Availability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every formal workbench list with member-safe server-side numbered pagination, give desktop navigation and content independent scrolling, and prevent unimplemented menu entries from navigating to broken pages.

**Architecture:** Add one strict numbered-page contract shared by Worker services and frontend data clients, then migrate endpoints as complete backend-to-UI vertical slices. Keep route implementation availability in a framework-neutral shared registry consumed by both navigation serialization and SPA routing; keep database menus responsible only for hierarchy and authorization. AppShell owns desktop scroll boundaries while mobile keeps document scrolling.

**Tech Stack:** TypeScript 7, React 19, Vite 8, Vitest, Cloudflare Workers, D1, Tailwind CSS 4, shadcn/ui source components.

**Spec:** `docs/superpowers/specs/2026-08-28-unified-pagination-shell-menu-availability-design.md`

## Global Constraints

- Default pagination is exactly `page=1` and `pageSize=20`; supported page sizes are exactly `20 | 50 | 100`.
- Reject invalid, duplicate, and unknown query parameters with HTTP 400.
- Reject `(page - 1) * pageSize >= 10_000` with HTTP 400; a page beyond the last page but inside the window returns HTTP 200 with empty items and true metadata.
- Every SELECT has a deterministic final `id` tie-breaker, and COUNT and SELECT share identical filters and authorization scope.
- Private COUNT and item queries bind the authenticated member ID from the principal, never from query or body input.
- Use Cloudflare Workers and D1 only; add no paid Cloudflare service, cache, queue, or external pagination dependency.
- D1 schema changes are append-only migrations; do not edit migrations `0001` through `0032`.
- Use official shadcn/ui source components and existing project primitives; do not introduce a closed runtime UI library.
- Migrate each endpoint's backend, data client, UI, and tests together; do not support cursor and numbered protocols simultaneously on one formal page endpoint.
- Every task follows red-green-refactor and ends in an independently reviewable commit.

- [ ] **Step 3: Implement the minimal shared contract**

```ts
export const supportedPageSizes = [20, 50, 100] as const;
export type SupportedPageSize = typeof supportedPageSizes[number];
export interface NumberedPageRequest { page: number; pageSize: SupportedPageSize; }
export interface PageMetadata extends NumberedPageRequest { total: number; totalPages: number; }
export interface NumberedPage<T> { items: T[]; pagination: PageMetadata; }

export function pageOffset(request: NumberedPageRequest): number {
  const offset = (request.page - 1) * request.pageSize;
  if (!Number.isSafeInteger(offset) || offset >= 10_000) throw new AppError("PAGE_INVALID", "Page is outside the query window", 400);
  return offset;
}
```

`parseNumberedPageRequest` must iterate `url.searchParams.keys()`, require one value per key, allow only `page`, `pageSize`, and the supplied filter whitelist, and call `pageOffset` before returning. `queryNumberedPage` must execute `[countStatement, rowsStatement]` in one `db.batch`, require a finite non-negative integer count, map rows, and return `buildPageMetadata`.

```ts
export interface FrontendPageMetadata {
  page: number;
  pageSize: 20 | 50 | 100;
  total: number;
  totalPages: number;
}

export function visiblePageTokens(page: number, totalPages: number): Array<number | "ellipsis"> {
  const keep = new Set([1, totalPages, page - 1, page, page + 1].filter((value) => value >= 1 && value <= totalPages));
  const sorted = [...keep].sort((a, b) => a - b);
  return sorted.flatMap((value, index) => index > 0 && value - sorted[index - 1]! > 1 ? ["ellipsis", value] : [value]);
}
```
