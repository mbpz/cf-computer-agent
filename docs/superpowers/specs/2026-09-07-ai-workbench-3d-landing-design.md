# Memory Garden · AI 知识工作室公开首页设计

日期：2026-09-07。

状态：用户于 2026-09-07 审阅后回复“通过”，本文设计规格已批准；不代表建模、前端实现、部署或验收完成。

范围：当前项目匿名根路径 `/` 的产品展示。首个核心为个人知识库，任务、看板、通知及上下文消息为辅助场景。登录后的工作台继续使用现有 shadcn 风格。

## 1. 目标与非目标

让初次访问域名的用户通过一个等距微缩工作室，看懂“收集资料 → 整理并阅读知识 → 基于来源提问 → 管理行动”的产品流程。可选择约一分钟的引导演示，也可直接点击功能热点或登录。

成功条件：不学习游戏操作也能完成演示；知道回答的来源在哪里；始终能找到登录入口；没有 3D 也能阅读全部说明并登录。

本期不做自由漫游、角色养成、物理玩法、多人联机、自动执行任务、公开真实 AI 聊天、访客上传和私有数据预览。不新增注册渠道，不改变邀请制、GitHub OAuth、用户隔离及权限规则。没有线上部署或数据库迁移授权。

## 3. 视觉语言与场景构图

选用等距微缩知识工作室，而非抽象光球或第一人称漫游。前者能把功能映射为易识别实体；后两种分别缺乏功能解释力或增加学习和性能成本。

- 主体：圆角矩形工作台及浅立体背板，开放式构图，知识书架和问答终端形成视觉中心。
- 材质：深石墨底座、暖白外壳、低饱和青绿色状态灯、少量暖金色资料标签；哑光为主，局部金属质感。
- 光照：柔和主光、明确接触阴影；不用大面积泛光、粒子雨或高频闪烁。
- 小型 AI 助手作为视线引导道具，使用简单刚体动作，不设计自动代办或通用智能的能力暗示。
- HTML 承担所有标题、正文、操作和翻译；模型不烘焙必须阅读的文字。
- 页面保持清晰留白及 shadcn 风格的按钮、边框和面板；不把整个登录后工作台改为游戏。

### 场景资产及命名契约

| 资产根节点 | 造型 | 对应说明与热点 |
| --- | --- | --- |
| `MG_Desk` | 台面、底座、背板 | 场景构图，无业务交互 |
| `MG_Inbox` | 托盘和独立资料卡 | 收集资料 `capture` |
| `MG_Library` | 书架、书册和展开阅读板 | 整理、审核、发布、阅读 `library` |
| `MG_Query` | 显示器与引用卡片 | 问答及来源核对 `answer` |
| `MG_Board` | 四列任务板和独立任务卡 | 待办、进行中、受阻、完成 `action` |
| `MG_Updates` | 小型通知与讨论侧屏 | 与任务或知识相关的更新 `updates` |
| `MG_Assistant` | 小型桌面机器人 | 轻量引导，不承诺自动执行 |

前三个功能区占主要视觉空间。节点名称保持稳定，场景配置将热点 ID 映射到节点、焦点镜头和 DOM 文案；缺失节点必须触发可见降级而非崩溃。

## 4. 页面与匿名路由

桌面首屏采用左侧产品说明、右侧大幅 3D 场景；较窄屏幕上下排列，不使用滚动劫持。首屏下方给出知识流程说明、隐私边界和重复登录入口，不增加无依据的统计数字或客户背书。

- 标题：让你的知识，成为每天的行动力。
- 描述：收集、整理、追问，在自己的工作台里连接知识与行动。
- 主操作：体验知识之旅。
- 登录操作：登录工作台，复用 `/auth/github`；同时展示邀请制说明。
- 演示区域始终显示“示例演示 · 不读取你的个人数据”，英文具有同等含义。

路由策略：

1. 匿名且路径为 `/`：展示新公开首页。
2. 匿名访问现有其他路径：保留现有登录页，不加载 3D，不新增重定向或 `returnTo` 语义。
3. 已登录访问 `/` 及工作台路径：保持现有行为，不挂载公开首页渲染器。
4. 会话检查失败：保留明确错误与登录提示，不伪装为正常匿名成功态。
5. 会话检查中：保持现有加载状态；本期不重构认证启动过程。

公开首页文案、静态 poster 和登录按钮不依赖模型加载。现有匿名 pageview 行为不扩展，不增加交互遥测。

## 5. 示例数据与演示状态

只使用随前端发布的人工编写虚构资料。示例主题为“如何整理个人项目资料”，包含两篇短文档、一条带固定来源引用的示例回答，以及一张配套任务卡。名称、作者和内容不取自本机文档、个人知识库或当前 Blender 文件中的私有信息。

演示推进由用户操作控制，无强制倒计时：

1. `overview`：全部场景可见，可开始、直接探索或登录。
2. `capture`：选择预置资料卡，动画进入收集托盘；明确未发生真实上传。
3. `library`：显示预置资料的摘要、审核与发布说明，用户打开对应示例正文。
4. `answer`：选择固定问题，展示固定回答；点击引用打开原文并定位对应段落。
5. `action`：展示配套任务；用户点击“演示移至完成”，只改变本地演示状态。明确并非产品自动从回答创建任务。
6. `complete`：总结已演示步骤，可重新体验或登录。

`updates` 是可随时打开的辅助热点，不阻断主流程。其内容是预置的上下文通知和讨论，不演示通用私信。

当前引导步骤、打开的热点、引用面板、动画暂停状态分别建模。关闭面板返回此前步骤；重播统一清空演示任务状态；刷新恢复初始状态，不写入持久存储。快速连续点击应收敛到最后一次选择，不堆积镜头动画。

所有热点均有等价的 HTML 按钮。鼠标指向仅作提示，不作为唯一交互方式。不提供假装可以输入任意问题的文本框。

## 6. 弹层、响应式与无障碍

- 桌面使用不遮挡关键操作的说明面板；窄屏使用可滚动的 sheet。嵌套引用在同一面板切换视图，避免叠加多个模态层。
- 每次只打开一个模态面板；外部遮罩点击和 Esc 均关闭，面板内部点击不误关闭。
- 模态开启时管理焦点和背景滚动；关闭后返回触发按钮。不得因画布重绘丢失焦点。
- 登录和示例选择均可通过键盘完成；热点标签不只依靠颜色，图标按钮具备可访问名称。
- 保持页面原生纵向滚动；画布不拦截触摸滚动或浏览器缩放，不提供自由 orbit 操作。
- `prefers-reduced-motion`、数据节省提示及显式“静态模式”优先展示 poster 与 HTML 演示；提供用户主动加载 3D 的入口。
- 语言切换复用当前语言运行时，切换后保留演示步骤；主题切换不重建整个场景。
- 不自动播放音频。本期不制作背景音乐。

## 7. 技术边界与组件职责

采用 Blender 制作的 GLB、静态 poster，加延迟加载的 Three.js 渲染模块；不增加物理引擎或另一套 React 3D 框架。选定依赖版本与许可证在实现计划阶段核对，不在设计中假定最新版本。

计划职责划分（以下为待创建模块，不表示已经存在）：

- `public-workbench-page`：组合品牌介绍、场景区、流程内容和登录操作。
- `workbench-demo-data`：中英文示例资料、引用、功能说明及 ID 关系。
- `workbench-demo-state`：纯状态转移与重置，独立于 WebGL 和网络。
- `workbench-scene`：延迟导入、资源加载状态、poster、错误边界与重试入口。
- `workbench-scene-runtime`：模型、镜头、热点投影、帧循环和 GPU 资源清理。
- `workbench-feature-panel`：可访问的说明、引用与演示操作。
- `workbench-scene-config`：节点 ID、镜头目标、热点及画质预算。

模型和 poster 通过现有 Vite/Worker 静态资源链路提供；构建时核对资源路径和生产 MIME 行为。沿用现有 API 鉴权和 Worker 路由，不因公开 GLB 放宽 `/api/*` 的鉴权；不改全局 `run_worker_first` 策略。

本期不新增 D1 表、R2、Workers AI、KV、Queue 或第三方模型生成 API；不调用付费资产服务。零新增付费依赖是设计约束，不是对现有账户用量或永久免费容量的保证。

## 9. 性能预算与失败处理

以下为待验收目标，不是测得结果：

- 单个公开 GLB 文件不超过 2 MiB；每个 poster 不超过 250 KiB。
- 导出场景不超过 60,000 三角形；交互时常规绘制调用目标不超过 80。
- 新增 3D 执行代码独立分包，gzip 目标不超过 250 KiB，不进入登录后工作台的启动依赖。
- 桌面像素比上限 1.5，移动端上限 1；纹理单边不超过 1024；优先使用材质颜色和静态接触阴影。
- 静止、页面隐藏或场景离开视口时停止不必要帧循环；相机及对象动画结束后按需渲染。
- 基准桌面目标 60 fps，参考手机目标 30 fps；验收记录具体设备、浏览器、分辨率和场景，不能用模拟截图宣称真机帧率通过。
- 模型加载超过 8 秒停止当前尝试并切换 poster；由用户明确重试，不无限循环请求。
- WebGL 不可用、导入失败、模型损坏、节点缺失或上下文丢失：均显示可理解的状态，保留 poster、HTML 演示和登录入口。
- 卸载时取消异步回调、监听器、定时器和帧循环，释放模型与渲染资源；重入或 React 开发模式重复挂载不得留下多套 canvas。

若资产超预算，先简化几何、材质和阴影，不以新增收费服务解决。本期不默认引入解码器；需要压缩扩展时须在实现中验证解码资源体积与本地托管方式。
