# 浏览器 VM 本机网络连接器设计补充

日期：2026-09-11

状态：用户已接受「首次安装或运行仅负责联网的本机连接器，VM 和终端仍在网页内」，并于 2026-09-11 要求「按照 checklist 顺序实现」。首个握手/来源隔离探针已实现并提交；2026-09-12（Asia/Shanghai）独立 HTTPS 静态预览已发布，内置浏览器获准的有效码握手与主动断开已通过。桌面 Chrome/Edge 权限矩阵、正式联网和组件安装仍未完成；未因此部署生产工作台。

基线：本地 `main` / `387ee77`。继承 `2026-09-09-browser-linux-vm-design.md` 的用户隔离、两种环境、分页、幂等和 shadcn 要求；只修订网络出口和连接器边界。发生冲突时，本补充的网络条款优先，旧验证记录保留。

## 1. 已确认的产品决定

- Linux、终端执行、内存和检查点仍在访问者浏览器中；连接器不托管 Linux，不执行 shell，不读取宿主文件。
- VM 网络通过访问者电脑出站；Cloudflare 只承载现有管理与授权职责，不中转下载数据、不运行 VM。
- 允许设计首次安装/手动运行的本机网络组件。这不是开机启动、常驻守护、修改代理、安装信任根证书、开放公网端口或远程部署的授权。
- 不把文件导入、GitHub API 或浏览器读取一个资源当作客体原生 `apk`、Git、HTTPS 联网。
- 首版联网范围仍是允许域名的出站 TCP 80/443；不新增 SSH、通用 UDP、入站服务、访问本机或局域网的能力。
- 保留个人环境和临时环境；它们是环境类型，不是两种不同的网络出口。

## 2. 组件与数据路径

```text
浏览器内 Linux → v86 虚拟网络 → 网页的本机连接适配层
                                     ↓
                           本机回环网络连接器
                                     ↓
                           经允许的公网 TCP 目标

工作台鉴权/环境归属 → 短期联网授权 → 本机连接器验证
```

连接器仅转发经过授权的字节流。远端 HTTPS 的 TLS 会话由客体应用建立和校验，不解密 HTTPS、不注入站点 Cookie、不导出浏览器登录状态、不安装中间人证书。Git 私钥、令牌等留在用户控制的客体环境内，不由连接器自动收集或代填。

只监听明确的回环地址，不能绑定 `0.0.0.0` 或任意网卡。网页不能要求连接器对任意 URL 发请求，也不能通过连接器访问其管理接口。固定工作台来源、端点和目的地址策略由连接器校验，不能只依赖前端按钮或 CSP。

现有 `tools/browser-vm/relay/local-relay.mjs` 可作为受限 WISP/TCP 探针的参考，不直接升级为正式连接器：它仅有开发票据、固定目标和有限会话，不具备生产成员鉴权、安装维护与正式域名兼容性证据。

## 3. 第一准入门：HTTPS 页面连接本机

优先验证浏览器在默认安全配置下，是否允许 HTTPS 工作台通过显式用户操作连接回环 WebSocket。具体协议和权限提示必须由实际目标浏览器证据确定，不能因为旧 HTTP 本地页面成功就指定生产可用。

验证必须使用有效证书的 HTTPS 页面、目标浏览器默认安全配置及仅回环监听的临时探针。证书错误豁免、关闭 Web 安全、禁用混合内容检查、开发者实验开关和页面伪造安全上下文都不计验收。

记录以下结果：

- 页面来源、操作系统、浏览器完整版本、连接目标和协议。
- 用户允许、拒绝、撤回本机网络权限时的结果；不触发无限重试。
- CSP、混合内容、本地网络权限、证书、端口占用和连接器未运行的错误类别；未经证据不猜测原因。
- 未授权其他网站的连接是否在任何外网拨号前被拒绝；`Origin` 缺失或为 `null` 同样拒绝。
- 本机组件退出后，页面进入明确的离线状态，旧连接不能复用。

如果回环 WebSocket 在目标浏览器不通过，不静默加装扩展或信任根，也不改走云中继。保留失败证据，单独提出扩展/native messaging 或受信任本机 TLS 的新取舍，请用户批准后才继续。

2026-09-12 已核对 Edge 147 官方正文中 WebSocket 本地网络限制及豁免说明；Chrome 检索摘要与再次打开的发布说明正文不一致，完整版本和权限范围仍待核对。来源与差异记录于 `design/browser-vm/local-connector-probe-evidence.md`。内置浏览器一次成功不能确定桌面浏览器默认策略，不将历史知识或检索摘要单独作为支持承诺。

## 4. 配对、账户隔离与撤销

正式产品必须同时满足设备侧配对和工作台成员授权；仅知道本机端口不构成授权，仅校验 Origin 也不构成成员身份认证。

1. 用户主动启动连接器，在本机确认允许的工作台来源，再在网页发起配对。不允许网页扫描端口寻找其他本机服务。
2. 本机确认使用有界、一次性的配对凭据；原始凭据不进入 URL、持久存储或日志。尝试次数与有效期受限，失败需要用户重新操作。
3. 工作台从认证主体派生成员，检查环境归属、`workspace.vm`、运行代次和网络策略。浏览器自行声明的 member/environment 字段不能作为连接器的授权依据。
4. 首次联网票据绑定工作台来源、连接器身份、成员、环境、运行代次、策略版本和唯一标识。连接器验证来自工作台的授权及自身绑定，原子消费后才允许任何 DNS/外网拨号。
5. 沿用原规格一次性票据 60 秒有效、连接租期最多 60 秒、30 秒续租的待验收默认值。续租必须检查当前身份与策略，不因 WebSocket 存活就永久联网。
6. 退出、账户切换、环境删除、运行代次改变和本机撤销主动断开。失去服务端联系或租期到期关闭流；本机重启不恢复旧票据或会话。

正常客户端主动关闭与连接器租期失效分别验收，不宣称离线浏览器能瞬时收到服务端撤销。被用户完全控制的本机进程不是抵御恶意设备所有者的信任边界。

## 5. 目的地址、DNS 与代理

- 首轮只使用现有三个公开诊断域名，继续保留失败证据。正式 Git 跳转、软件源依赖域名必须在验证后纳入明确策略，不因报错自动扩展为任意域名。
- 每条连接验证规范化域名、端口和解析结果，拒绝本地/私网/链路本地/保留地址及 IPv6 映射形式；固定连接到已经验证的地址，防止检查后重新解析。
- 现有三个合成客体 IP 只用于探针。生产 DNS/域名映射需要独立契约及测试，不能把它当作通用 DNS 已实现。
- 第一切片验证本机系统路由下的直接 TCP 出站。它不自动继承浏览器的 PAC、代理扩展或浏览器独有认证。
- 若直接出站不能稳定访问源站，停止公网验收并请求明确的代理配置选择；不读取浏览器配置/密码，不自行更改系统网络或切换镜像。
- 代理模式不得只校验代理地址而放过真实目的地址。实现前须明确 DNS 解析与目标 IP 固定策略；无法保留目的地址防护的代理模式不启用。
- 每环境最多 8 条 TCP 流，所有缓冲、连接等待和空闲时间都有上限；背压和取消必须释放资源。跨设备额度和服务端撤销仍需正式授权切片验证，不能把本机计数器声称为可靠的全账户额度。
- 只记录有限的状态、目标域名、错误类别、时间和字节计数；不记录令牌、请求正文、终端输出、完整证书或宿主网络配置。

## 6. 生命周期与用户体验

网页状态建议为：未运行连接器 → 待本机确认 → 待联网授权 → 已连接；失败区分浏览器限制、配对失效、授权失效、目标被拒、网络不可达。不把这些状态归并为“VM 启动失败”。

VM 可保持运行但处于离线。停止联网只关闭网络；停止 VM 同时释放其网络；关闭连接器撤销全部本机活动授权。恢复快照默认离线，显式新授权后只发起新的用户请求，绝不自动重放 `apk`、Git 推送或 API 写入。

正式界面继续使用 shadcn、中英文、深浅主题、键盘及点击外部关闭弹层规则。第一准入门通过前，不新增可误认为已交付的正式导航或联网开关。

## 8. 本轮证据与下一阶段边界

已确认的方向来自用户本轮「接受」。可复用的历史源码/验收线索为：

- 固定 v86 包的 `FetchNetworkAdapter` 与 `WispNetworkAdapter`，分别是 HTTP Fetch 适配和 WISP 字节流路径，不混为同一能力。
- `tools/browser-vm/relay/local-relay.mjs` 与 `destination-policy.mjs` 的开发身份、目的地址和资源限制。
- 总计划「浏览器所在电脑直连下载」及 `design/browser-vm/g0-evidence.md` 的真实浏览器失败/成功记录。

本轮只修改设计和进度文档，不生成长期凭据，不安装连接器或更改机器网络。下一阶段优先实现 LC-003～005 的本地兼容性与隔离探针；任何公网 HTTPS 验收页面的发布另行授权，不复用生产域名部署权限。
