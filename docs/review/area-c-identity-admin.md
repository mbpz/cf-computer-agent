## 结论摘要

1. **新密码认证存在 3 个 P0 级安全/边界问题**：注册对任意邮箱开放（绕过 `ALLOWED_MEMBER_EMAILS` 与 invitation-only 声明）；忘记密码仅凭“邮箱+新密码”即可接管账户（无邮箱所有权证明，设计文档明确承认）；未验证注册可抢占 allowlist/bootstrap 管理员邮箱，GitHub 首登会被 link 到抢占记录且不提升角色，攻击者保留密码凭据。**代码实现与 README:39 及设计规格一致，但与 README:3“Access is invitation-only”、IDN-004“allowlist 控制成员”冲突，且与产品背景“私有邀请制”硬边界冲突**。
2. **GitHub OAuth、D1 哈希 Session、HMAC+APP_TOKEN automation 三项实现质量高，与账本声称一致**：state 绑定 + PKCE S256 + primary verified email、`__Host-` HttpOnly/Secure/SameSite=Lax、写入同源校验、禁用即时拒绝、退出幂等、签名覆盖 method/path+query/timestamp/nonce/body-hash、300s 时间窗 + D1 nonce 防重放、仅 legacy 能力、不能成为管理员。未发现可利用缺陷。
3. **授权体系“位图定义 → 服务端校验 → 前端可见性”存在多处不一致**：8 个 permission bit 被定义/可分配但从不校验（幽灵权限）；`analytics:read` 与 `audit:read` 双轨；系统 admin 角色不可缩减且其加位无实效；给 contributor 分配系统 admin 角色只得到部分 mask；管理组导航隐藏但部分管理只读 API 仍按 mask 放行（“API 允许但 UI 隐藏”）；自定义角色 `knowledge:review` 可打开 `/admin/submissions` 页面但全部审核 API 因 `role!=="admin"` 必然 403（“页面可达但必然 403”）。
4. **管理写操作整体达标**：成员状态 CAS+收敛重放、角色/菜单乐观并发、维护/资产回收操作回执（一次审计、幂等）、批量审核逐项结果与逐项操作号、审计 metadata 白名单不含正文/凭据、数字分页齐全。问题集中在审计 actor 归因（未认证重置记成成员本人）、死审计动作、过滤下拉漂移。
5. **VM/environments 边界诚实**：服务端只有元数据/生命周期事件，前端明示“不启动 VM、不建立网络连接、启动保持禁用”，与 WB-ENVIRONMENTS 的 partial 登记一致，未把未发布能力展示为可用。
6. **文档/证据有夸大与过期**：IDN-007 证据文档仍列已删除的 `migrations/0079_password_recovery.sql`、恢复码行为与 `count=79`（当前 78 个 migration），头部与末尾“移除恢复码”章节自相矛盾；`member.password_reset` 等新审计动作未进入审计筛选列表；0078 直接 `DROP TABLE` 与手册“migration 只能向前兼容，不能靠删表回滚”的表述冲突。账本对 IDN-007 的“本地 done、发布 pending”总体诚实，但未把“开放注册使 allowlist 不再是授权边界”写成风险。
