# 通知更新进行中与未知结果的离页保护（本地）

基线：`8571747`，分支 `codex/functional-checklist-completion`。
归属：C05、A05 / R2-008、导航计划 Task 4 逐页所有者核对。

## 发现的问题

标记已读、批量已读和打开目标在请求进行中，以及响应丢失后的只读恢复期间，侧栏和其他路由都可以直接离开。恢复文案已经说明重试只重新读取、不证明更新是否成功，但页面并不强制用户先看到这次读取的结果。

同一页的筛选、分页和越界收敛是既有对账路径：写入进行中仍要能切换当前视图，成功或失败后再按新视图核对。这条路径需要保留。

## 实际变更

- 更新进行中阻止普通离页和 `beforeunload`。本页筛选、分页和越界收敛用同步标记放行，不解除未完成的更新。
- 401/403 清空受保护内容并解除离页锁。其他失败进入既有只读恢复，并保持离页锁。
- 恢复后的重新读取如果失败，锁继续保留；列表和未读摘要都读回后才解除。读取失败不会被当成“更新已失败”的证明。
- 打开目标只有在回执匹配后才导航；导航前先解除本次更新的锁，因此其他页面自己的离页确认仍然生效。
- 守卫只在锁定期间注册，空闲通知页继续使用普通浏览器历史。

## 验证

- 新增行为先失败：进行中离开被放行、未知结果后离开被放行。既有用例改为通过正式筛选入口切换视图，不再用绕过准入的历史写入模拟离开。
- 通知路由、页面和壳层 3 文件 48/48。通知路由与共享位置、准入一起为 103 项通过。
- `npm run typecheck`、`npm run verify:i18n`、`npm run audit:functional-checklist` 通过。没有新增可见控件，操作清点不需要再生。
