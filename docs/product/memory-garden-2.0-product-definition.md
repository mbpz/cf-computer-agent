# Memory Garden 2.0 产品定义：Personal Work OS

版本：2.0 baseline  
日期：2026-09-08  
状态：待用户审核，尚未进入实现计划

## 1. 产品定义

Memory Garden 2.0 是一个以个人为中心、以 AI 为核心、以知识为记忆、以项目和任务为执行主线、以协作和治理为团队扩展能力的私有 Personal Work OS。

AI 知识库是工作台的记忆系统，不再是整个产品的边界。产品要帮助用户完成完整闭环：

```text
收集 → 整理 → 理解 → 规划 → 执行 → 协作 → 复盘 → 沉淀
```

## 2. 目标用户与边界

### 2.1 用户

- 个人用户：管理自己的信息、目标、项目、任务和 AI 工作流。
- 小团队成员：在授权空间内共享知识、项目、任务和讨论。
- 管理员：管理成员、权限、菜单、空间、统计、审计和系统配置。

### 2.2 硬边界

- 保持 Cloudflare 免费层优先。
- 首期支持 5–20 人私有团队。
- 保持 GitHub OAuth 白名单登录；微信登录暂不启用。
- 保持 admin/contributor 主角色和现有权限位图模型。
- 不把 R2、Vectorize、Queue、企业级多租户作为 2.0 核心依赖。
- 大文件原件、外部连接器和高级自动化采用后续阶段或可选能力。

## 3. 产品分层

```text
工作台 SaaS
├── 工作入口层：今日、收件箱、命令中心、最近活动
├── 信息资产层：知识、笔记、文件、链接、代码、模板
├── 工作执行层：目标、项目、任务、日程、会议
├── AI 智能层：Copilot、结构化生成、Agent、自动化
├── 协作层：评论、讨论、审核、通知、团队活动
└── 治理层：成员、权限、菜单、空间、统计、审计、设置
```

## 4. 核心对象模型

| 对象 | 作用 | 关键关系 |
| --- | --- | --- |
| Workspace | 工作台边界 | 包含成员、空间和配置 |
| Space | 信息与权限分区 | 包含知识、项目和资产 |
| InboxItem | 未整理输入 | 可转换为知识、任务、项目或日程 |
| Goal | 方向和结果 | 关联项目、任务和复盘 |
| Project | 有边界的工作集合 | 关联目标、任务、知识、成员 |
| Task | 可执行行动 | 关联项目、知识、日程和评论 |
| KnowledgeItem | 长期记忆单元 | 关联来源、版本、引用、任务 |
| Asset | 文件、链接、模板等资料 | 关联知识、项目或任务 |
| Conversation | AI 或团队对话 | 可产出知识、任务和决策 |
| ActivityEvent | 活动与审计事件 | 关联主体、操作者和时间 |
| Member/Role/Menu | 身份与治理 | 决定可见性和操作能力 |

## 5. 一级产品模块

### 工作台

默认入口，展示今日重点、收件箱、任务、项目、最近知识、AI 建议和活动时间线。

### 收件箱

承接随手笔记、文本、链接、文件、AI 结果和待处理事项；用户可以把内容转换为知识、任务、项目、日程或归档。

### 知识与 AI

保留现有文本、Markdown、代码、PDF、Office、表格、网页快照、审核、版本、搜索、引用、AI 问答和学习能力，并升级为统一信息资产中心。

### 工作管理

覆盖目标、项目、任务、子任务、依赖、日程、会议和复盘。任务必须能够关联知识和项目。

### 协作

覆盖评论、讨论、提及、审核、通知、成员活动、决策记录和团队空间。

### 资产

覆盖文件元数据、链接、代码片段、模板、会议记录和可复用资料。免费层下优先保存规范化文本和元数据。

### 数据

普通用户查看个人活动、贡献、任务和阅读数据；管理员查看站点访问、登录、地域、活跃度、AI 使用和内容质量统计。

### 管理

继续使用成员、角色、位图权限、菜单树、空间、标签、审计和系统设置。

## 6. 交互原则

- 2D 工作台是权威产品；3D 是可选的空间化总览和展示模式。
- 顶部提供全局搜索、命令中心、语言、主题和用户菜单。
- 左侧导航负责模块切换，中间区域负责主任务，右侧区域负责上下文操作。
- `Cmd/Ctrl + K` 可以搜索任意对象、创建对象、切换空间或调用 AI。
- 所有对象都有明确的空、加载、错误和无权限状态。
- 所有用户可见文案必须经过 i18n；禁止显示 `undefined` 或内部 key。
- AI 输出必须携带来源、时间、置信度和信息缺口。
- 3D、动效和外部连接器不能阻塞核心工作流。

## 7. 权限与安全

```text
Member → Role → Permission Bitmap → Menu Visibility → API Capability
```

- GitHub OAuth 只允许 `ALLOWED_MEMBER_EMAILS` 中的 primary/verified 邮箱。
- 普通成员只能访问授权空间和自己的私有对象。
- 管理员路由、统计和治理接口必须服务端校验。
- 成员禁用后，已有会话重新访问时必须拒绝。
- 所有权限和治理变更写入审计。

## 8. 不属于 2.0 核心的能力

- 公开社区和开放注册。
- 无限文件存储和原件归档。
- 企业级多租户计费。
- 复杂组织层级和 ABAC 策略语言。
- 多百个外部连接器。
- 依赖付费 Cloudflare 产品的异步基础设施。

## 9. 2.0 成功定义

- 用户打开首页即可理解今天的工作状态。
- 收件箱内容可以在一个工作流内转换为知识、任务或项目。
- 知识、任务、项目、目标和 AI 输出可以互相跳转。
- 普通用户和管理员看到的导航与数据严格隔离。
- AI 输出 100% 带可追溯来源或明确标注没有来源。
- 2D 核心流程不依赖 3D、R2 或外部连接器。
- 在 Cloudflare 免费层边界内支持 5–20 人稳定使用。
