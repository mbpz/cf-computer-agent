# 登录后工作台与管理端：统一交互设计调研

日期：2026-10-15。状态：**研究与候选方案，未经用户选型；不是已批准设计、实现计划或验收结果。**

## 1. 意图与边界

用户要求以 beUI 为组件基础，重新设计登录后工作台、全部管理页面的整体交互风格，覆盖完整页面头部、操作区域、展示区域等。先调研方案，再决定实现。

- 目标不是只换配色，而是统一导航、信息层级、动作位置、内容模板、编辑与恢复方式。
- 不改公开落地页与登录页，不借此次工作调整后端授权、成员隔离或数据模型。
- 现有 URL、权限、分页、操作编号与幂等、未知写入恢复、草稿保护、撤权清屏继续有效。
- 功能缺失不能通过新 UI 文案或假数据假装补齐；批量操作、统计、排序等须先核对实际 API。
- 工作台与管理页共享视觉基础，但不能为了“统一”把聊天、阅读器、看板、终端都强制做成表格。
- 实现前还需选定方向、评审书面设计与实施计划；本研究不授权安装、覆盖组件、推送或部署。

## 3. 三个候选方向

以下是本项目的设计提案，不是对参考产品的复刻或官方认证。

| 方向 | 视觉与交互 | 优势 | 代价与风险 |
| --- | --- | --- | --- |
| **A：清晰工具型工作台（推荐）** | 延续蓝色强调色；中性底、实色数据面；头部紧凑；固定操作层级；克制反馈动效 | 能同时承载知识、任务、AI 与高密度管理操作；较易保留现有品牌与布局行为 | 必须把标题、工具栏、抽屉、状态规则做好，否则只会变成普通后台 |
| B：知识书桌 | 暖灰底、低饱和植物色；阅读与编辑留白较多；轻层级、弱边框 | 适合阅读、沉淀、个人知识产品定位 | 权限矩阵、审核、审计等密集页面仍需紧凑模式，容易产生两种密度割裂 |
| C：深色操作台 | 石墨底、清晰分区、少量冷色强调；并列面板；快捷操作突出 | 适合 VM、Agent、图谱、监控式操作 | 长文阅读与大量管理表单不一定合适；不能靠高对比发光和常驻动画表达“高级” |

推荐 A 为全站基础，同时借用 B 的阅读宽度控制和 C 的多面板组织方式。浅色、深色是同一设计的主题，不是两个互不相同的产品。

## 4. 推荐方案 A：固定页面骨架

```text
┌ 左侧主导航 ──────┬ 全局顶栏：当前位置 / 全局搜索 / 通知 / 账号 ────────┐
│ 工作台          │ 页面头部：标题 + 必要摘要         次动作  [主动作] │
│ 知识            │ 视图与操作区：Tabs / 搜索 / 筛选 / 排序 / 更多     │
│ 工作            │ 已选条件；或批量选择操作条（按场景出现）            │
│ 协作            ├ 主展示区 ──────────────────┬ 可选上下文侧栏 ────┤
│ 管理            │ 表格 / 阅读 / 看板 / 聊天   │ 预览、关联、属性   │
│                 │ 图谱 / 时间视图 / 终端      │ 非所有页面常驻     │
│                 ├ 分页、总数或任务状态 ───────┴────────────────────┤
│ 账号与设置      │ 编辑视图可用固定保存条，普通页面不占此区域          │
└─────────────────┴──────────────────────────────────────────────────┘
```

### 4.1 全局外壳

- 导航分组沿用现有模块语义，管理功能不是另一套皮肤；具体可见项仍由服务端权限决定。
- 全局顶栏仅承载跨页动作，不重复页面标题，不把创建任务、审核发布等局部动作塞进顶栏。
- 桌面侧栏可折叠；窄屏改为导航面板，不额外叠加一条装饰性 dock。
- 面包屑只出现一次；参数详情带可靠的返回来源，而非一律回首页。
- 既有通知未读与注销错误状态不能因改版退化成图标或 toast。

### 4.2 页面头部

- 一个页面一个明确标题；下方最多一行必要上下文，例如当前空间、筛选范围、对象状态。
- 页面级主动作通常一个；其余动作分为次要动作与“更多”。审批页允许并列语义清晰的通过/拒绝，而不是机械限制按钮数量。
- 不为每页放大标题或统计卡。统计仅在帮助当前任务且数据真实可得时出现。
- 私有、只读、已归档、权限受限等信息应显式可见，不只依赖颜色。
- 头部字段、按钮尺寸和响应式重排由共享 PageHeader 负责，不由各页复制 className。

### 4.3 操作区域

- 内容范围切换用 Tabs；数据查询用搜索/筛选；展示形态切换用列表/看板等视图控件，三者不混成一排等权按钮。
- 搜索、筛选、排序、刷新位置一致；应用后保留可移除条件与清空入口。
- 列表查询保留输入与旧结果，提供局部加载反馈，不因请求开始卸载整页。
- 选中条目时出现批量动作区，明确“当前页”还是“跨页”；不把只加载了一页的选择伪装成全部。
- 仅在后端支持、对象允许且用户有权限时提供对应动作；没有 API 的排序、批处理不提前画成可用功能。
- 具体批量写入需逐项结果和失败恢复，不能只用一个总成功 toast。

### 4.4 展示区域与滚动

- 数据列表桌面用统一 Table 容器、表头与分页位置，沿用服务端分页与稳定行标识。
- 窄屏不强塞全列：选取主标识、状态、关键元数据；其余在详情中展开。关键操作不得仅 hover 出现。
- 分清全页滚动、表体滚动、画布滚动三类；禁止无意叠加多个纵向滚动容器。
- 阅读页控制正文宽度，代码与宽表局部横向滚动；看板/图谱/终端使用剩余空间而非正文宽度。
- 普通列表不默认摆一整块创建表单。轻创建放单一抽屉，复杂提交流程用完整页面；高频快速录入可保留轻量行内入口。

### 4.5 编辑与反馈

- 查看详情优先可深链、可恢复的主从视图；简短编辑可用抽屉，复杂审核/发布保留详情页。
- 对话框只承载短、明确的决定。移动端轻筛选可用 bottom-sheet，长表单使用全屏编辑。
- 弹层关闭、Esc、浏览器前进后退、切换页面统一经过已有草稿与写入守卫；组件自带关闭行为必须接入守卫。
- 表单包含 dirty、提交中、成功、确定失败、结果未知、权限撤销等状态，不把请求超时直接显示为“保存失败，可以重新创建”。
- beUI button-stateful 的加载/成功/失败外观不能代替业务状态机；未知结果应保留原操作编号和精确核验入口。
- 字段错误就地显示；操作错误留在相应面板；全局 toast 只做辅助反馈，不承载唯一恢复入口。
- 焦点在弹层打开、错误出现、关闭后有明确落点；撤权后清理不再有权显示的数据。

### 4.6 建议视觉参数（待选型，不是现有事实）

- 8px 间距节奏；桌面内容边距 24px、窄屏 16px；单独为高密度页面定义 compact 模式。
- 页面标题建议 22–24px，正文/操作文字 14–16px；中文和英文分别验证截断与换行。
- 控件建议 8px 圆角、容器 12px；状态标签与按钮不统一做成大胶囊。
- 原有蓝色强调色先保留，选定方向后再实测浅深主题的文字、边界和焦点对比。
- 实色内容面；半透明材质仅用于少量外壳/覆盖层，不在所有数据卡片上叠 blur。
- 动效主要解释选中、展开、提交、视图切换；建议短反馈 120–180ms、面板过渡 180–240ms，最终以真机验证为准。
- 支持 reduced motion；触屏不依赖 hover；不默认加入磁吸、数字滚动或整页入场动画。

## 5. 全页面模板覆盖矩阵

这是路由级初步覆盖表。每页还需补头部字段、主/次/行/批量动作、权限、加载/空/错/未知状态和真实用例。

| 模板 | 覆盖入口 | 头部/操作区 | 展示区与重点 |
| --- | --- | --- | --- |
| 个人工作概览 | `/`、`/today`、`/focus`、`/review` | 日期或周期、必要状态、当前任务动作 | 今日重点、专注上下文、复盘；不把所有页面改成统计仪表盘 |
| 工作对象列表 | `/tasks`、`/inbox`、`/goals`、`/projects` | 对象标题、新建、过滤、排序、视图 | 一致数据列表与详情/编辑入口；保留关系、状态变更确认 |
| 多维工作视图 | `/boards`、`/calendar`、`/projects/:id/timeline` | 时间/分组范围、视图切换、对象动作 | 看板、现有时间数据视图、时间线；新日历网格或拖动能力另核业务支持 |
| 知识浏览 | `/knowledge`、`/search`、`/my-submissions` | 查询、范围、筛选、提交入口 | 结果为主；收藏/笔记/研究/最近访问有清晰层级，不无条件堆在列表上方 |
| 知识阅读 | `/knowledge/:id` | 标题、版本、来源、收藏/引用动作 | 正文、目录、关联与笔记；保护草稿和未决写入 |
| 内容提交 | `/submit` | 提交类型与状态、提交动作 | 文本/文件输入、上传队列、校验、恢复；不缩进小抽屉 |
| AI 工作区 | `/agent` | 会话、来源范围、历史入口 | 流式回答、引用、执行进度、输入区；阅读时不强制拉回末尾 |
| 图谱/环境 | `/graph`、`/environments` | 当前范围或环境、生命周期动作 | 画布/检查器，或环境列表/终端/文件；不创建第二套全局导航 |
| 协作 | `/notifications`、`/messages`、`/messages/:id` | 未读/上下文/过滤 | 通知与线程主从结构、独立加载/发送/撤权反馈 |
| 账号设置 | `/settings` | 设置标题、必要说明 | 分组设置、即时生效或保存规则明确；避免每个选项包一张大卡 |
| 管理概览 | `/admin`、`/admin/analytics` | 范围、刷新、有效操作 | 真实指标、趋势、待处理入口；日期和统计口径一致 |
| 管理队列 | `/admin/submissions`、`/admin/assets`、`/admin/duplicates`、`/admin/audit` | 队列范围、筛选、允许的操作 | 表格与详情预览；审核、资产、去重、审计分别保留语义；审计不提供虚构编辑动作 |
| 管理详情 | `/admin/submissions/:id` | 当前对象与状态、审核决策 | 正文/附件与上下文；发布、拒绝等明确影响且独立恢复 |
| 管理配置 | `/admin/members`、`/admin/roles`、`/admin/menus`、`/admin/spaces` | 对象标题、权限内创建/配置 | 成员列表、角色权限矩阵、菜单树、空间关系；同一视觉语言，不强制同一控件 |

共享状态另列：无权限、未找到、首次加载、刷新、空数据、无筛选结果、网络失败、局部失败、过期/冲突、写入未知、只读、移动窄屏。

## 6. beUI 候选组件与接入边界

下表 slug 已与 S1 实时目录核对。尚未执行安装，也未逐个确认源码能直接满足本项目全部业务守卫。

| 区域 | 候选 slug | 使用约束 |
| --- | --- | --- |
| 外壳 | `animated-sidebar`、`command-palette` | 优先保留现有权限导航、路由守卫及账号逻辑；整体替换须核对功能对等 |
| 按钮/工具栏 | `button-base`、`button-stateful`、`overflow-actions` | 有标签的主动作保持可见；未知写入状态由业务适配层控制 |
| 筛选/视图 | `tabs`、`select`、`combobox`、`popover` | 当前视图与筛选状态可恢复；键盘和长中文标签需验证 |
| 数据 | `table`、`table-async`；确有需求才用 `table-editable` | 优先复用现有 DataTable，不用组件内的本页排序冒充服务端全量排序 |
| 详情与编辑 | `drawer`、`bottom-sheet` | 关闭行为接既有守卫；不默认嵌套；长任务使用页面 |
| 状态 | `loader`、`animated-toast-stack` | 复用现有适配；错误/未决状态不能只放在短暂提示中 |
| Agent | `chat-app`、`prompt-input`、`message-scroller`、`agent-activity`、`citations` | 先评估完整 workspace 组合，再只取实际需要的构件；业务会话、来源、取消和恢复不交给演示状态 |

依赖审查发现：部分候选引入 `lucide-react`，而当前项目配置为 Phosphor；`table` 涉及 `@tanstack/react-virtual`，`chat-app` 涉及 `shiki` 等依赖。不能把整个 registry 打包进主入口。是否调整组件内部图标，需要明确批准；不擅自覆盖现有 helpers、motion 与守卫适配。

## 7. 建议下一阶段交付顺序

1. **选风格**：A/B/C 同一份真实任务列表内容做对照，避免三张互不相关的宣传稿。可视化对比须用户同意后制作。
2. **验证跨业务一致性**：用任务列表、成员管理、角色权限矩阵、知识阅读、Agent 五类代表页验证所选语言。
3. **书面设计评审**：明确 token、PageHeader、ActionBar、ContentSurface、Inspector、FormActions、状态契约及完整页面迁移矩阵。这些是项目共享组合，不冒称 beUI 官方组件。
4. **实施计划评审**：按共享基础 → 普通列表 → 配置/审核 → 阅读/AI → 图谱/VM 顺序，小批迁移；一页一份行为回归证据。
5. **实现与验收**：获得所需确认后实施。每批做角色隔离、键盘、窄屏、中英文、浅深主题、错误恢复和包体检查。

### 验收底线

- 34 类入口及其页内编辑器有对应模板与状态矩阵，不以“共用了一个组件”代替逐页验证。
- 页面主动作位置一致；数据阅读与操作区分清楚；筛选、分页、选中、返回上下文行为可解释。
- 所有可关闭表面都遵守 pending/dirty/unknown 语义；无鼠标也可完成主要操作。
- 320/375/768/1280 视口、中英文、浅深主题与 reduced motion 都有代表性验证。
- 普通用户不因组件替换看到无权数据；管理员可见入口与服务端权限一致，仍需实际验证。
- 新表格、聊天、编辑器与管理路由按需加载；重设计不能把登录后依赖重新压回公开首页主包。
- 首屏字节、加载与交互性能比较使用同一构建口径和设备/网络条件；不把本地压缩比直接当线上体验。
