# 子任务与依赖的版本条件写入（本地）

基线：`604e64e`，分支 `codex/functional-checklist-completion`。
归属：C01。

## 发现的问题

进度、标签和关联已经按版本拒绝过期写入。子任务和依赖还没有：

- 两个客户端改同一子任务时，后一次 PATCH 会盖掉标题、状态或顺序。
- 依赖的添加和移除不看父任务版本。过期的移除仍会删掉依赖。

任务编辑器目前没有这两类控件。接口已经对外开放，所以版本规则要先在接口上成立。

## 实际变更

不带 `expectedUpdatedAt` 时行为不变。

- `PATCH /api/tasks/:id/subtasks/:subtaskId` 可带子任务自己的 `expectedUpdatedAt`。标题、状态、顺序已经一致时不写库；否则版本不符返回 `409 TASK_VERSION_CONFLICT`。更新使用 `AND updated_at = ?`，新版本严格递增。
- 删除子任务可在 JSON 正文里带同一版本。空正文仍直接删除。子任务已经不存在时是 404，不说成版本冲突。
- `POST /api/tasks/:id/dependencies` 和对应 DELETE 可带父任务的 `expectedUpdatedAt`。依赖已经存在时添加按无操作成功；已经不存在时删除仍是 404。真正新增或删除才会占用父任务版本。
- 非法版本字符串返回 400。

## 验证

- 服务单测先失败：过期的子任务标题仍被接受。修复后同一用例覆盖子任务 409、一致重放、非法版本 400、过期删除 409、已删除 404，以及依赖的 409、重放和已删除 404。
- 真实 D1 的任务 HTTP 用例走同一路径，45/45（含原有任务与结构约束用例）。
- Worker 类型检查、操作清点（前端未改，241 文件、1049 个候选）和清单审计通过。清单仍是原 30、范围内 29、关闭 5、开放 24。
