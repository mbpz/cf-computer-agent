# 审核评论未知写入跨刷新保留（本地）

基线：`dd7d96b`，分支 `codex/functional-checklist-completion`。
归属：R6-003 与 A05，不关闭这两个父项。

## 发现的问题

审核评论用客户端编号保证同一条评论不会写两次。结果丢失后，这个编号只留在当前挂载里。刷新后提示消失，再次提交会换成新编号，可能写成第二条评论。

## 实际变更

已登录成员发出前，先把评论编号和冻结正文记在当前标签页，并按成员和投稿分开。记不进去就不发送。刷新或重新挂载后仍显示结果未知，离开被挡住；重试和重新读取都用原来的编号，不会自动再发。核对成功或首次明确拒绝后清掉记录；清不掉则继续锁住。记录损坏时不能再写评论，离开不被挡住，只能显式丢弃；丢弃不改变工作数据。没有成员身份时不记录。

## 验证

三条评论用例先失败：刷新后存储是空的，记不进去仍会发送，坏记录也不拦操作。修复后同一组用例要求重挂载不自动重发、离开被挡住，重试使用原编号，成功后记录消失；记不进去则不发送；坏记录可丢弃后才允许提交。评论所有者 32/32，相关审核前端 82/82。前端类型、文案静态检查、操作清点（245 文件、1058 个候选，不是运行验收）和清单审计通过。清单仍是原 30、范围内 29、关闭 5、开放 24。
