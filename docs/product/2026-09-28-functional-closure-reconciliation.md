## 为什么长期显示“剩余 28”

1. 原清单计数单位是 30 个父任务，排除发布 D08 后为 29；先前只勾选 B03，其他已完成子项不会使父任务计数下降。28 不是“28 个完全没实现的功能”。
2. 前批持续补 C03/C04 等大父任务的原子实现，却没有完成 A03/A04 这种可独立关闭的核对交付物。继续重复报告 28 掩盖了局部进展，也未解释真实关闭条件。这是推进和汇报方式的问题。
3. 部分条目同时包含本地功能、原生浏览器功能验收和发布后验收。按 2026-09-25 已确认范围，发布/远程迁移/生产验收只归 D08，不再阻塞本轮功能关闭；但真实双身份、原生浏览器键盘/触控等功能验收并未被取消，不得用 happy-dom 或 fixture 身份代替。
4. 旧成熟度 manifest 的 `partial` / gap 是保守的整体能力维度，不等于每个 gap 的历史文字仍准确描述代码；新实现应读增量证据，不能继续以旧文字把已修复功能当作未实现，也不能因单个修复而删除整条历史 gap。
