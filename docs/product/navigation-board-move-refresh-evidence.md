# 看板未知移动的跨刷新恢复（本地）

基线：`ef7e933`，分支 `codex/functional-checklist-completion`。
归属：C02、A05 / R2-008、导航计划 Task 4。

## 发现的问题

上一片只在同一次挂载内记住“结果未知的移动”。刷新、关闭后重新进入看板或路由重新挂载后，锁和核对入口一起消失：页面显示的是回滚后的列，没有任何提示说明那次移动可能已经保存。刷新提醒只能劝阻，不能保留结果未知的事实。

## 实际变更

- 新增 `frontend/lib/board-move-intent.ts`：按标签页、按成员存放一条移动记录（任务 id、标题、源状态、目标状态），格式与收件箱、专注的意图记录一致。
- 发出请求前先写记录并读回校验；写不进去就不发请求，提示“没有发出，任务未改变”，不加锁。
- 匹配回执或明确 4xx 拒绝（含 401/403）后清除记录。传输失败、5xx、408/429、畸形回执保留记录。
- 重新挂载时读到记录就恢复为未知移动：显示同样的核对/原样重试提示，禁用移动，阻止普通离页和 `beforeunload`。核对只做 GET；重试使用同一目标，状态写入是绝对值幂等。
- 清除记录失败时不解锁：继续显示未知移动并提示再次核对，避免留下下次进入才冒出的孤立记录。
- 记录损坏、属于其他成员或字段不合法时视为“无法读取”：禁用移动但不阻止离页（离开不会丢失任何东西），只允许成员显式丢弃，丢弃不改动任何任务。
- 没有成员身份的预览模式不写记录，保持原有行为。

## 验证

- 路由新增 8 项，其中 7 项先失败后通过（明确拒绝那项原本就不写记录）：发出前已有记录且成功后清除、刷新后恢复锁并核对解锁、刷新后同目标重试、拒绝清除、成员隔离、损坏记录阻止移动并可丢弃、记录写入失败不发请求、清除失败保持锁定。

## 边界及清单

记录存在 `sessionStorage`，跟随标签页：刷新和站内导航后保留，关闭标签页后不保留，另一个标签页看不到。跨标签并发写同一任务仍是后写覆盖，核对会如实报告“已在别处被更改”，但没有版本条件写入。原生浏览器、真实双身份与键盘/移动端验收仍开放。
