# 任务进度、标签、关联的版本条件写入（本地）

基线：`752e435`，分支 `codex/functional-checklist-completion`。
归属：C01。

## 发现的问题

字段和状态已经按读到的版本拒绝过期写入，进度、标签和关联仍按绝对值后写生效：

- 一个标签页把进度改成 40 之后，另一个仍拿旧版本提交 80，会直接覆盖。
- 标签是整组替换。后写的一组会清掉先写的标签。
- 关联的添加和移除不看任务版本。过期的移除仍会删掉关联。

## 实际变更

服务端仍向后兼容：不带 `expectedUpdatedAt` 时不因版本拒绝。

- `POST /api/tasks/:id/progress`、`PUT /api/tasks/:id/tags`、`POST /api/tasks/:id/links` 可带 `expectedUpdatedAt`。结果已经与请求一致时按无操作成功，不写库、不重复审计，未知结果重发仍幂等。结果不同且版本不符时返回 `409 TASK_VERSION_CONFLICT`。
- 进度用 `AND updated_at = ?` 条件更新。标签替换和关联增删先占用同一任务版本再改子表，成功后 `updated_at` 严格递增。
- 删除关联可在 JSON 正文里带 `expectedUpdatedAt`。空正文的删除保持原样。关联已经不存在时仍是 404，不把“已经删掉”说成版本冲突。
- 版本字符串不合法时返回 400。创建任务时附带的知识关联不另占一版。

前端：

- 编辑器保存进度、标签、添加或移除关联时带上读到的 `updatedAt`。409 沿用“已在别处更改”提示，重新读取并保留该子表单草稿。
- 可序列化意图可以带上这个版本，刷新后的重试仍发送同一请求。不带该字段的旧记录仍然有效。

## 验证

- 服务单测先失败：过期进度被接受。修复后同一用例覆盖进度、标签、关联的 409、一致重放不重复审计、已删除关联的 404，以及非法版本的 400。
- 真实 D1 的任务 HTTP 用例：过期进度/标签/移除关联为 409，一致重发成功，审计只有一次进度、一次标签、一次关联和一次解除。任务 worker 文件与服务单测、编辑器路由、意图记录一起 131/131。
- 全量单元测试 320 文件 4572/4572。类型检查、UI 构建、双语 13/13、文案静态检查、操作清点（241 文件、1049 个候选，不是运行验收）和清单审计通过。
- 清单审计仍是原 30、范围内 29、关闭 5、开放 24。
