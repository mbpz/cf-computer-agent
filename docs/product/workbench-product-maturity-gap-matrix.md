# Workbench 产品成熟度缺口矩阵

本矩阵是 R0 审计到 R1–R8 实施阶段的唯一缺口分派账。它不表示缺口已实现，只表示现有 manifest 与 domain audit 中每项已记录缺口的稳定身份、唯一主责原子、前置依赖和独立验收路径已经确定。

## 记账规则

- Gap ID 固定使用 `<capability-id>:<dimension>:<slug>`；文案调整不改变同一产品问题的身份。
- `Source` 中的 manifest 指纹绑定当前原始 gap 文案；domain source 绑定 Task 3 已接受的 endpoint 级 mutation-safety gap。
- 每个 source 只出现一次、只指定一个 `Owner atom`。跨模块协作通过 `Prerequisites` 表达，不重复主责。
- `P0` 是用户阻断、授权、隐私或写入收敛风险；`P1` 是完整产品闭环；`P2` 是已有本地能力的发布/真实浏览器证据。表格严格按优先级排序。
- owner 可以依赖同阶段或更早阶段原子，不能依赖更晚阶段。所有状态仍以 checklist 与交付总账为准。
