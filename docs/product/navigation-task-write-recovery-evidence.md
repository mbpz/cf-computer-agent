# 任务编辑器未知写入的只读核对与跨刷新恢复（本地）

基线：`e98035b`，分支 `codex/functional-checklist-completion`。
归属：C01、A05 / R2-008、导航计划 Task 4。

## 发现的问题

- 结果未知时只能“重试原操作”。重试遇到 4xx 一律仍算未知，例如任务已在别处改过、状态转换不再合法时返回 422，编辑器就一直锁定：不能关闭、不能离开，只能刷新。
- 刷新后锁和重试入口一起消失，回到列表也看不出那次写入可能已经生效。旧提示要求“勿刷新”，但刷新本身没有被真正处理。
- 创建在一次尝试失败、用户再点创建时会生成新的任务 ID。如果第一次其实已经落库，就会出现两条任务。

## 实际变更

- 每种写入（创建、修改字段、状态、进度、标签、添加/删除关联）都描述为可序列化意图，统一用 `runTaskWrite` 发送、用 `taskWriteOutcome` 与一次新读取比较。所有操作都是绝对值或按 ID 去重的写入，重发同一意图不会产生第二次效果。
- 未知状态新增“核对结果”：只做 GET。读到的结果与意图一致即视为已保存，推进对应子表单基线；不一致则解锁并保留草稿，提示“任务上没有这次更改，可再次提交”。任务 404 时：创建视为未保存，其余视为任务已不可用。核对失败保持锁定。
- 创建在确认之前始终复用同一个任务 ID，“未保存”之后再点创建也不会多出一条任务。
- 发出前按标签页/成员把意图写入 `sessionStorage` 并读回校验；写不进去就不发请求。匹配回执、明确 4xx 拒绝（含 401/403）或核对出结论后清除；清除失败保持锁定，并提示再次核对。
- 刷新或重新挂载时，路由读到记录就重新打开对应编辑器（创建则恢复原字段），处于同样的未知锁定状态，阻止普通离页和 `beforeunload`。
- 记录损坏或属于其他成员时，任务页显示“记录无法读取”，写入不会发出，只能显式丢弃；丢弃不改动任何任务。没有成员身份的预览模式不写记录。

## 验证

- 编辑器路由新增 10 项，9 项先失败后通过（明确拒绝那项原本就不写记录）：核对为未保存时保留草稿、核对为已保存、状态重试 422 后靠核对解锁、未保存后再次创建复用同一 ID、发出前已有记录且成功后清除、刷新后恢复字段修改并核对、刷新后恢复创建并同 ID 重试、成员隔离、记录写入失败不发请求且损坏记录仅可丢弃。
- 意图模块单测 21/21；任务相关 4 文件 126/126；全量单元测试 320 文件 4557/4557。
- `npm run typecheck`、`npm run build:ui`、`npm run test:i18n`（13/13）、`npm run verify:i18n`、前端操作清点重新生成并通过 `--check`、`npm run audit:functional-checklist` 通过。
