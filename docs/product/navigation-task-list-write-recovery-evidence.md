# 任务列表快捷状态/删除的未知结果分流（本地）

基线：`c9b5abc`，分支 `codex/functional-checklist-completion`。
归属：C01、A05 / R2-008、导航计划 Task 4。

## 发现的问题

任务列表行上的“完成/重新打开”和“删除”在网络失败、5xx 或畸形回执时都显示“无法更新任务”。这些情况下服务端可能已经执行：

- 删除可能已经生效，页面却说失败，并允许用户再次确认删除。
- 状态可能已经改变，列表却仍显示旧状态，没有任何核对入口。
- 写入进行中可以直接离开页面。

## 实际变更

- 列表行的状态切换和删除改用编辑器同一套可序列化意图（新增 `delete` 操作，404 视为已删除），发出前按标签页/成员记录，写不进去不发请求。
- 明确 4xx 拒绝（408/429 除外，含 401/403）清除记录：401/403 清屏，其余显示“无法更新任务”。
- 传输失败、5xx、408/429、畸形回执进入列表级未知状态 `data-task-list-unknown`：说明是哪一条任务，所有行操作和新建被锁定，阻止普通离页和 `beforeunload`；本页筛选、分页仍可用（同步 owned 标记放行）。
- “核对结果”只做 GET：一致即已保存；不一致提示“任务上没有这次更改，可以再试一次”；删除时 404 即已删除。“重试原操作”发送同一意图；重试被拒绝不证明之前那次失败，只提示核对。
- 写入进行中同样阻止离页。
- 刷新后：创建和字段修改重新打开编辑器（草稿可见），状态、进度、标签、关联、删除改由列表级提示核对。
