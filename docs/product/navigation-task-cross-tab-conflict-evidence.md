# 任务跨标签并发冲突：版本条件写入（本地）

基线：`fd97d49`，分支 `codex/functional-checklist-completion`。
归属：C01、C02。

## 发现的问题

两个标签页打开同一任务时，后保存的一方会静默覆盖先保存的一方：

- 编辑器的字段修改是无条件 PATCH，另一标签页刚改过的标题、备注会被旧内容覆盖，没有任何提示。
- 看板移动和列表快捷状态只校验状态机是否允许，不知道页面看到的状态已经过期。例如一个标签页已把任务改为“阻塞”，另一个标签页仍按“待办”拖到“进行中”，也会被接受。

## 实际变更

服务端（向后兼容，不带新字段时行为不变）：

- `PATCH /api/tasks/:id` 可带 `expectedUpdatedAt`。字段已与请求一致时按无操作成功（不写库、不重复审计），这样未知结果的重发仍然幂等；否则版本不符返回 `409 TASK_VERSION_CONFLICT`。写入使用 `AND updated_at = ?` 条件更新，读与写之间的竞争同样返回 409；新的 `updated_at` 严格递增，同一毫秒内的两次写入也能区分版本。
- `POST /api/tasks/:id/status` 可带 `expectedStatus`。已在目标状态仍按原来的绝对值语义成功；否则当前状态与预期不符返回 `409 TASK_STATUS_CONFLICT`。
- 版本字段格式不合法时返回 400。

前端：

- 编辑器保存字段时带上读到的 `updatedAt`，保存状态时带上读到的状态；收到 409 时提示“已在别处更改，没有保存”，重新读取最新版本，并保留本子表单的草稿，用户再次保存时会带新版本、有意覆盖。
- 列表快捷状态带上行状态，看板移动带上源列状态；收到 409 时提示已在别处更改，并重新读取列表或全部列。
- 可序列化意图记录携带这些预期值，刷新后重试仍发送同样的请求体。

## 验证

- 服务端单测新增 2 项先失败后通过；真实 D1 + HTTP 的 worker 测试新增 1 项：旧版本 PATCH 409、一致重发 200、过期状态 409、已到目标 200，审计只记一次更新和一次状态变更。worker 任务 20/20。
- 前端新增 4 项先失败后通过：编辑器发送版本并在 409 时重新读取且保留草稿、编辑器发送预期状态、列表 409 提示并重新读取、看板 409 回滚并重新读取四列。另有 4 项旧用例只是精确断言请求体，补上预期状态字段。
