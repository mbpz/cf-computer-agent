# 本机握手准入探针（开发验收工具）

仅校验 HTTPS 页面到本机回环 WebSocket 的握手。**没有 VM、TCP 出站、DNS、宿主命令、宿主文件接口或成员联网授权。** 不接入工作台导航，不安装常驻服务，不修改代理或证书。

## 手动运行

从仓库根目录使用现有依赖运行：

```sh
rtk proxy npm run dev:browser-vm:connector -- https://YOUR-APPROVED-PREVIEW-ORIGIN 9876
```

第二个参数为可选的明确端口；省略时操作系统分配空闲端口。页面不扫描端口。HTTPS 来源必须精确匹配，不带尾部斜杠、路径、查询或用户信息。只绑定 `127.0.0.1`。端口占用会报启动失败，不自动换端口或归因浏览器权限。

1. 打开终端显示的本机控制页，确认启动参数中允许的来源。
2. 点击生成一次性配对码。原始码只在本机响应与页面短暂出现，不写入地址、日志或持久存储。新码会使旧待用码失效；30 秒过期；五次失败尝试后不能继续使用。
3. 在已获准发布的 HTTPS 探针页面填写同一端口和配对码，点击验证。提交立即清空输入框。不要发送配对码给第三方、保存截图或记录请求正文。
4. 记录结果，不改变浏览器默认安全配置。握手期限 3 秒（从 WebSocket 建立开始）；页面连接等待最多 15 秒；服务端会话 60 秒，客户端另有 65 秒硬时限。最多四条连接，帧最大 1 KiB。
5. 停止探针时在启动终端按 Ctrl+C；会关闭全部连接。没有后台安装或开机启动项。

本机页「清除显示」只清除页面内容，**不是撤销码**；要使未消费的旧码立即失效，生成新码或停止探针。

## HTTPS 文件与安全门槛

2026-09-11 用户已授权独立 HTTPS 验收预览，仅限下述三个静态文件及必要的安全响应头，不修改生产工作台。发布账号检查发现 Wrangler 登录令牌过期且无法刷新，等待用户在本机重新登录；目前没有创建任何公网站点。

只需要发布同目录的 `probe.html`、`page.mjs`、`client.mjs`，不发布本机控制页、`server.mjs`、仓库源码或环境配置。部署端应设置 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`，以及响应头 CSP：

```text
default-src 'none'; script-src 'self'; connect-src ws://127.0.0.1:*; base-uri 'none'; frame-ancestors 'none'; form-action 'none'
```

通配符只允许**回环地址的端口**；客户端仍只连接用户明确填写的一个端口。这个策略不构成绕过浏览器混合内容或本地网络权限限制的许可；实际是否允许必须实测。不能为了成功放宽 `default-src`、关闭安全策略、使用自签证书豁免或复用其他网站作为探针页面。

控制页自己的 HTTP 页面不是 LC-003 证据；即使浏览器把 localhost 视为安全上下文也不算有效证书 HTTPS 页面。使用 Node 人为设置 HTTPS Origin 的测试仅证明服务端分支，不能证明浏览器支持。

## 结果记录

逐次记录操作系统、Chrome/Edge 完整版本、HTTPS 页面来源、实际配置端口、权限选择和最终状态。不要仅以缩减过的 User-Agent 代替完整版本。

浏览器 WebSocket 的普通 error 事件不足以区分缺少组件、Origin 拒绝、CSP、权限、混合内容或证书问题。页面统一显示「原因未确定」，需要浏览器明确诊断和人工操作记录才能细分。只有协议关闭明确给出拒绝时显示「握手被拒绝」，仍不推断具体凭据失效原因。

待真实验收：允许、拒绝、撤回权限；组件未启动/退出；非法来源；普通关闭与重新配对。未通过第一准入门前，不进入 LC-006 正式授权或把 `apk` / Git 标为可用。

## 自动化验证

```sh
rtk proxy npm run test:browser-vm:connector
```

服务端测试使用真实本机 HTTP/WebSocket，页面状态测试使用受控传输事件。不会拨号公网，也不会使用用户凭据。
